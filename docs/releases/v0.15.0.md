# v0.15.0 — Managed graph and corpus explorer skills

MAADb 0.15.0 ships two new managed agent skills so operators and agents can
treat projects as typed information graphs and map unfamiliar corpora —
without adding ontology engines, graph UIs, or query languages to the core.

## Highlights

- **`_skills/graph-ontology.md`** — choose among `maad_related`,
  `maad_relationship_paths`, `maad_join`, and ref-chain `maad_aggregate`;
  densify prose/`mention` links into typed `ref` fields; light ontology
  conventions in `_skills/local/ontology.md`.
- **`_skills/corpus-explorer.md`** — staged protocol from `maad_summary` /
  schema / samples / paths / integrity to a project-owned
  `_skills/local/corpus-map.md`.
- Registered in `MANAGED_ARTIFACTS` (4 → 6) with stamp/refresh lifecycle.
- Listed in `MAAD.md` Skills; densification notes folded into
  `architect-core` and `schema-guide`.
- Upgrade behavior: next bind **creates** the two new skill files
  (create-if-absent); existing managed files are not rewritten. `MAAD.md`
  becomes `outdated` until `maad instructions refresh`.

Design background remains in [`docs/proposals/rich-skills/`](../proposals/rich-skills/).

## Verification

- 1,274 tests passed; 6 skipped.
- CI passed on Ubuntu and Windows for the feature PR.
- No new production dependencies.
- No database schema changes.

## Known limitations / migration

- Host-side visualization, dashboards, and report publishing stay outside
  `@maadb/core` (see proposal host-boundary notes).
- Projects that never bind and never refresh simply never receive the new
  skill files until they do.
- If agents edit a managed skill file in place, it classifies `modified` and
  blocks refresh without `--force` — project notes belong in `_skills/local/`.
