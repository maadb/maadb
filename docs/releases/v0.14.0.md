# v0.14.0 — Per-project history modes

MAADb 0.14.0 adds an explicit Git history policy to every project while
preserving the behavior of existing unconfigured projects.

## Highlights

- Five modes: `audit`, `feed`, `read`, `batch`, and `snapshot`.
- Compatibility inference: projects with Git use `audit`; projects without Git
  use `feed`.
- Explicit Git-backed modes fail with `GIT_NOT_INITIALIZED` when the project
  root is not a Git repository. MAADb does not silently downgrade the mode.
- Project configuration in `instance.yaml`, with
  `MAAD_HISTORY_MODE_DEFAULT` as the environment fallback.
- Admin-only `maad_flush` MCP tool and `maad flush` CLI command.
- Pending-write recovery across thresholds, timers, explicit flushes, clean
  shutdown, and startup.
- `maad_health.history` telemetry for mode source, pending writes, successful
  flushes, failures, and migration advisories.
- Snapshot mode flushes pending writes before creating an annotated
  `maad-snapshot-*` recovery tag.

See [History modes](../history-modes.md) for configuration, migration,
recovery, and operational details.

## Verification

- 1,270 tests passed; 6 skipped.
- CI passed on Ubuntu and Windows.
- No new production dependencies.

## Known limitations

- `history_options` is validated but ignored when supplied with `audit`,
  `feed`, or `read`.
- Startup recovery can consolidate several failed pending `audit` writes into
  one recovery commit.
- The opt-in benchmark isolates feed and Git stages; it does not yet execute
  batch or snapshot mode or calculate batch amortization.
